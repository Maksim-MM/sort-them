# Game Design Document (GDD): Project CarSort

## 1. High Concept & Core Loop
* **Жанр:** 3D-симулятор сортировки от первого лица / Cozy Cleanup / Completionist. Игра конечна, у неё есть финал.
* **Сеттинг:** Склад-магазин игрушечных машинок в стиле Low-Poly.
* **Аудио-визуальный стиль:** Мягкая палитра, расслабляющий лоу-фай эмбиент, тактильные щелчки пластика/металла при установке деталей.
* **Звук (требования утверждены 06.09):**
  * Музыка и эффекты регулируются отдельными ползунками.
  * Треки музыки переключаются граммофоном (раздел 6).
  * Эффекты по событиям: установка в слот, отскок чужой модели, бросок, закрытие полки. Закрытие полки — приятный короткий звук (в референсе это щелчок пальцами, не хор), громкость не должна пугать.
  * Взятие машинки в руку: звук не на каждое взятие, а случайно или на каждое N-е, параметр в конфиге.
  * Гудок по кнопке (раздел 4). Звук мотора как вариант звука события обсуждается при подключении ассетов.
  * Референс ругали за слишком тихую музыку относительно эффектов и за резкий звук закрытия секции; баланс микса проверяется на этапе 5.
  * **Реализация (07.09):** каждое событие имеет своё поле клипа в `GameConfig`, пустое поле = тишина без ошибок, так что набор звучащих событий настраивается в инспекторе. Хуки стоят на: установка в слот (`PlaceClip`), отскок (`BounceClip`), бросок (`ThrowClip`), закрытие полки (`ShelfCompleteClip`), взятие в руку всегда (`PickupClip`, решение 07.09 вместо «каждое N-е»), подбор канистры, активация способности и «не готова», покупка, смена фокуса в меню (`UiMoveClip`), клик по кнопке (`UiClickClip`), шаги ходьбы и бега (`FootstepWalkClip/RunClip`, интервалы в конфиге, в приседе реже и тише), музыка (`MusicClip`, зациклена, громкость из настроек). Прыжок и приземление не озвучиваются. Готовность способности после отката: звук (`AbilityReadyClip`, заглушка `ability_ready.wav`) и вибрация (07.09). Мировые звуки играют в точке события через пул `Sfx` с лёгким случайным питчем; звуки UI и способностей без позиции. Синтезированные заглушки в `Assets/_Game/Audio/`: установка, закрытие полки, взятие, шаги, бег, смена фокуса, покупка, лоу-фай петля 32 с; остальные поля пустые до боевых ассетов. Музыка играет с начала игры, трек переключается радио (раздел 6).
* **Core Loop:**
  $$\text{Сбор из кучи} \longrightarrow \text{Сортировка по полкам} \longrightarrow \text{Заработок валюты} \longrightarrow \text{Прокачка в терминале} \longrightarrow \text{100\% порядок}$$

## 2. Архитектура данных (Data-Driven)

Система строится без хардкода наименований через ScriptableObjects / JSON-конфиги.

### CategoryData
* `string CategoryID` — уникальный ID категории (`cat_muscle`, `cat_supercars`, `cat_emergency`).
* `LocalizedString DisplayName` — ключ локализации названия («Маслкары», «Спецтехника»). Пакет Unity Localization.
* `Color CategoryColor` — цвет индикатора на стеллаже.

### RackData
* `string CategoryID` — категория, за которой закреплён стеллаж.
* `int ShelfCount` — количество полок в стеллаже (задаётся на этапе дизайна уровня, не в коде).

### ShelfData
* `int Rows`, `int Columns` — раскладка слотов на полке, `Capacity = Rows × Columns`. Обычная полка 2 ряда × 5 = 10, особые полки больше (референс).
* `float SlotPitch`, `float RowPitch` — шаг слотов по ширине и по глубине; `float SlotYaw` — поворот предмета в слоте вокруг вертикали (0 = мордой к игроку, ~35 = три четверти). Всё это данные полки, не код: `LevelBuilder` читает их из ассета `Shelf_Standard` и не перезаписывает (с 06.09).
* **Габаритная коробка игрушки (спецификация для ассетов, 06.09):** высота ≤ 0,32 м, длина ≤ 0,42 м, ширина ≤ 0,22 м. Сетка полок выводится из этой коробки и угла установки, а не наоборот: при `SlotYaw` 35° игрушка занимает ~0,47 м в глубину и ~0,42 м в ширину, отсюда `RowPitch` 0,48 и `SlotPitch` 0,45. Генератор заготовок ужимает модели под коробку; боевые ассеты делаются под неё.

### CarItemData
* `string CarID` — уникальный ID модели (`car_mustang_red`).
* `LocalizedString DisplayName` — ключ локализации названия модели («Красный маслкар '69»).
* `string CategoryID` — привязка к родительской категории.
* `GameObject Prefab` — Low-poly префаб с Rigidbody, Collider и звуковым триггером.
* `float DisplayPrice` — цена на ценнике полки. Декоративная, на награду не влияет (референс: Sort Them Ducks).

### EconomyConfig (один SO на игру)
* `float RewardPerCar` — награда за валидно установленную машинку. По умолчанию 1, как в референсе.
* `float ShelfCompleteBonus` — бонус за закрытие полки. По умолчанию 0, в референсе бонуса нет.
* Баланс хранится как `float`/`decimal`, не `int`: в референсе видны значения вида $176.5, множители слот-машины дают дробные суммы.
* `bool AllowNegativeBalance` — баланс может уходить в минус при снятии после трат. По умолчанию true.

### UpgradeData (один SO на улучшение)
* `string UpgradeID`, `LocalizedString DisplayName`, `LocalizedString Description`, `Sprite Icon`.
* `int[] CostPerLevel` — стоимость каждого уровня. Длина массива = число уровней, бинарный апгрейд = массив из одного элемента.
* Параметры эффекта по уровням (например `float[] ValuePerLevel`).
* Цены сейчас берутся из референса, балансируются в конце, когда утверждён полный набор моделей. В код не зашиваются.

## 3. Механика стеллажей и полок (Shelf System)

### Иерархия
* **Стеллаж (`RackController`):** закреплён за одной категорией (`CategoryID`) с начала игры, один стеллаж на категорию (утверждено 06.09, как в референсе). Над стеллажом вывеска категории: иконка + `DisplayName`, цвет `CategoryColor` (референс: Sort Them Ducks). Содержит `RackData.ShelfCount` полок; в прототипе 10 полок в двух секциях по 5, по одной полке на модель категории. Подсветка способностью обводит весь стеллаж.
* **Высоты полок (утверждено 06.09):** верхняя полка на уровне глаз или чуть выше, чтобы содержимое верхних полок читалось с 2 м и вплотную (референс). В прототипе шаг полок 0,42 м, полки на 0,25/0,67/1,09/1,51/1,93 м, глаза на 1,70 м. Следствие для контента: высота модели не больше ~0,32 м, генератор заготовок ужимает более высокие модели до этого предела.
* **Полка (`ShelfController`):** принадлежит стеллажу, вмещает `ShelfData.Capacity` слотов (`SlotPoint[]`) с точками привязки (`Transform`). Хранит только одну модель.
* **Форма полки не фиксирована:** полка знает только список точек слотов, их расставляет дизайнер. Прямая полка стеллажа и круглая полка-витрина — один и тот же `ShelfController` с разной раскладкой точек. Особые полки для особых машинок: больше 10 слотов, круглая форма (референс).

### Правило полки
* **Empty:** Полка пуста, модель не назначена. Принимает любую модель любой категории.
* **Assigned:** Первая установленная машинка задаёт `TargetCarID`. Другая модель физически не ставится: машинка отскакивает от полки и падает рядом (референс: Sort Them Ducks). Смешать две модели на одной полке невозможно. Начатую полку нужно добить до полной, разыскивая оставшиеся экземпляры модели по уровню.
* **Валидность — свойство полки, не машинки:** полка валидна, если категория `TargetCarID` совпадает с категорией стеллажа. Невалидная полка может стоять сколько угодно, это допустимая временная раскладка.
* **Reset:** Если все машинки сняты с полки, она возвращается в `Empty`. Категория стеллажа не сбрасывается никогда.
* **Манипуляция:** Игрок может забрать любую машинку с полки обратно в инвентарь. Снятие возвращает выплату за неё, чистого штрафа нет.

### Состав мира
* Каждая модель присутствует на уровне в количестве, кратном `ShelfData.Capacity`, иначе полка для неё недостижима и 100% невозможен. Инвариант проверяется EditMode-тестом `ContentInvariantTests` по запечённой раскладке и сцене: число экземпляров каждой модели равно вместимости полки, полок в категории столько же, сколько моделей, машинок на уровне столько же, сколько слотов. Урок референса: расхождение счётчиков делало 100% недостижимым.
* Все машинки лежат на уровне с начала игры, поставок и волн нет. Референс: Sort Them Ducks.
* Первая версия — одна комната со всеми машинками. Разбиение на тематические комнаты/сцены — только если упрёмся в производительность, см. бэклог.

### Валидация и индикация ценника (Price Tag)
У каждой полки есть табличка/дисплей на середине полки. Референс: Sort Them Ducks.
* **Скрыт:** полка в статусе `Empty`. Появляется при назначении `TargetCarID`, исчезает при сбросе в `Empty`.
* **Содержимое:** название модели и декоративная цена `DisplayPrice`. Счётчика нет. Табличка небольшая, висит на торце полки и не закрывает обзор машинок.
* **Белый цвет (Valid):** категория модели на полке совпадает с категорией стеллажа. За каждую машинку начисляется `EconomyConfig.RewardPerCar`.
* **Красный цвет (Invalid):** модель на полке из чужой категории. Выплата не начисляется, `PaidAmount = 0` у каждой машинки на полке.

### Экономика установки и снятия
* Награда плоская: `RewardPerCar` ($1) за каждую валидно установленную машинку, независимо от модели. Цена на ценнике декоративная.
* На экземпляре машинки хранится `PaidAmount` — сколько за неё реально выплачено при установке (`RewardPerCar` или 0, если стояла невалидно).
* При снятии с полки списывается ровно `PaidAmount`. Поставил/снял = чистый ноль, перестановка бесплатна, эксплойта «поставил-снял-поставил» нет. Невалидная машинка: +0 при установке, −0 при снятии. Референс: Sort Them Ducks, проверено.
* Бонуса за закрытие полки нет (референс). Если когда-нибудь включим `ShelfCompleteBonus`, он платится один раз за модель (`CarID`) и не списывается.
* Баланс может уходить в минус (снял машинки после трат в терминале). UI показывает отрицательный баланс красным. Кламп в ноль недопустим — это эксплойт.
* **Триггер завершения (Completion):** При `Capacity/Capacity` валидных машинок:
  1. Ценник становится золотым.
  2. Проигрывается звук закрытия полки (`GameConfig.ShelfCompleteClip`, назначается в инспекторе; поле утверждено 06.09).
  2а. Все машинки полки одновременно «пружинят»: масштаб 1 → `PopScale` (1.15) → 1 за `PopDuration` (0.25 с). Утверждено 06.09.
  3. Дополнительной выплаты нет: за последнюю машинку начисляется обычный `RewardPerCar` (референс, проверено). `EconomyConfig.ShelfCompleteBonus` по умолчанию 0, оставлен как ручка.

## 4. Контроллер игрока и манипуляция объектами

* **Камера:** First-Person (вид от первого лица). Покачивания при ходьбе нет. Высота камеры сглаживается (`GameConfig.CameraHeightSmoothTime`, ~0,12 с), чтобы ходьба по куче не трясла картинку; в прыжке и падении сглаживание почти отключено. Капсула игрока широкая (`PlayerRadius` 0,45 м), чтобы не проваливаться в щели между машинками. Урок референса: укачивание было главной причиной возвратов, лечили сглаживанием камеры патчем.
* **Инвентарь:**
  * Базовая емкость: 5 слотов (`0/5`), расширяется апгрейдом.
  * В инвентаре одновременно могут лежать разные модели.
  * Скролл колесом мыши выбирает активную машинку (референс).
* **Взаимодействие (раскладка референса Sort Them Ducks):**
  * **ЛКМ:** Взять машинку под прицелом с пола или из кучи. С полки машинки снимаются в обратном порядке установки: прицел на полку или на любую машинку на ней подсвечивает контуром последнюю поставленную, ЛКМ забирает её.
  * **ПКМ, прицел на полке:** Поставить активную машинку в следующий свободный слот по порядку (Raycast, зелёный силуэт превью показывает этот слот). Порядок заполнения: с дальнего правого угла полки (относительно игрока) справа налево по заднему ряду, затем передний ряд. Точка прицела на полке не влияет на слот.
  * **ПКМ, прицел не на полке:** Бросить активную машинку по физической дуге. Бросок — единственный способ выкинуть предмет из инвентаря. С апгрейдами «Более сильный бросок» и «Авторасстановка при броске» превращается в установку с расстояния.
  * Одна кнопка на установку и бросок исключает случайный бросок при прицеливании в слот: действие определяется тем, куда смотрит игрок, а не длительностью нажатия.
* **Ввод: Input System, три схемы.** Логика работает только с действиями, устройства ей не видны. Привязки — по референсу, без переназначения игроком.

| Действие | Клавиатура/мышь | Геймпад | Приоритет |
| :--- | :--- | :--- | :--- |
| `Move` | WASD | левый стик | ядро |
| `Look` | мышь | правый стик | ядро |
| `Interact` (взять) | ЛКМ | RT | ядро |
| `PlaceOrThrow` | ПКМ | LT | ядро |
| `NextItem` / `PrevItem` | ось скролла с накоплением (см. ниже) | LB / RB | ядро |
| `Sprint` | Shift | нажатие левого стика | после апгрейда |
| `Crouch` | Ctrl | B | после апгрейда; переключатель, не удержание (07.09) |
| `Jump` | Space | A | ядро |
| `Ability1..3` | 1 / 2 / 3 | крестовина | после апгрейдов |
| `Zoom` | Z | X | не приоритет |
| `Horn` (гудок) | средняя кнопка мыши | нажатие правого стика | не приоритет |
| `Pause` | Esc | Start | ядро |
| `UI/Navigate` | стрелки | крестовина / левый стик | ядро |

| `UI/Cancel` | — (Esc через `Pause`) | B / круг | ядро |

  * **Прокрутка инвентаря (утверждено 06.09):** ось `scroll/y` читается как значение, дельта накапливается; переключение при переходе порога, между переключениями пауза, накопленное сбрасывается после короткой паузы без ввода (`GameConfig`: `ScrollThreshold`, `ScrollMinInterval`, `ScrollIdleReset`). Одно поведение для колеса мыши и тачпада: дельта не меньше `ScrollNotchThreshold` за кадр считается щелчком колеса и переключает сразу; мелкие дельты тачпада накапливаются до `ScrollThreshold` с паузой `ScrollMinInterval` между переключениями, хвост инерции сбрасывается. На геймпаде LB/RB как кнопки. На таче тот же `Inventory.Next/Prev` вызывается тапом по списку. Порог проверять в браузерной сборке: браузер нормализует дельты по-своему.
  * Геймпад в WebGL работает через браузерный Gamepad API, раскладка кнопок у части падов обобщённая — тестировать в браузере.
* **Тач-схема (мобильные браузеры, с первого дня):** принята как черновик, проверяется на устройстве. Левая половина экрана — виртуальный стик, правая — обзор свайпом. Экранные кнопки дублируют геймпад: «Взять», контекстная «Поставить/Бросить», прыжок, спринт и присед после апгрейдов, способности 1–3. Инвентарь — тапабельная полоска слотов вместо скролла.
* **Обратная связь при наведении:**
  * Белый контур на машинке под прицелом. Тот же контур на терминале апгрейдов и других интерактивных объектах: всё, с чем можно взаимодействовать, обводится при наведении.
  * Зелёный силуэт в слоте полки, куда встанет машинка из рук.
  * Название активной машинки выделено в списке инвентаря (см. ниже), сама машинка видна в руке.
* **Предмет в руках (утверждено 06.09):**
  * Активная машинка рендерится как view-model перед камерой справа внизу: три четверти спереди, чуть сверху, масштаб ~0.85. Рисуется поверх геометрии (глубина сжата к ближней плоскости, самоперекрытие частей сохраняется).
  * Взятие: модель стартует из реальной позы машинки (как лежала на полу или стояла на полке) и за ~0.3 с перелетает в руку с доворотом. Взятая машинка становится активной.
  * Смена колесом: старая исчезает за ~0.1 с, новая въезжает из правого нижнего угла за ~0.3 с.
  * Бросок и установка: модель исчезает из руки мгновенно, физическая машинка появляется в позе руки и летит по дуге (бросок) или за `PlaceFlightDuration` (0.3 с) перелетает в слот с доворотом (установка, утверждено 06.09); встав, коротко «пружинит» масштабом. Следующая из инвентаря въезжает в руку.
  * Дальность взаимодействия и дистанция броска — параметры `GameConfig` (`BaseInteractRange`, `BaseThrowDistance`), апгрейды их умножают. Черновые базовые значения 2.2 м и 0.75 м (бросок уменьшен вдвое 06.09 по ощущениям); в референсе на первом уровне это около метра по горизонтали.
* **Список инвентаря на экране (утверждено 06.09):** справа внизу вертикальный список названий машинок в порядке взятия, активная строка яркая и крупнее, остальные приглушены, под списком счётчик `X/Y` жирным. Референс: Sort Them Ducks.
* **Сообщения на экране (утверждено 06.09):** общая система коротких уведомлений внизу экрана по центру: одна строка на тёмной полупрозрачной плашке, плавно появляется, висит ~2 с, плавно гаснет; новое сообщение заменяет текущее. Все тексты через ключи локализации. Первые сообщения, для способностей: попытка использовать способность на откате — «Способность ещё не готова»; попытка с пустыми руками — «Возьми что-нибудь в руки». Дальше система используется для других подсказок по мере надобности.
* **Обучение:** при первом запуске канвас с глифами кнопок: WASD — ходьба, мышь — обзор, ЛКМ — взять, ПКМ — поставить/бросить, скролл — выбор машинки. Закрывается любым действием. Без пошагового туториала (референс).
* **Меню с геймпада (утверждено 07.09):** в терминале и в меню паузы фокус ходит вверх-вниз по кругу крестовиной или стиком, с автоповтором при удержании. В терминале фокус встаёт только на кнопки «Купить», которые доступны сейчас (хватает денег, не максимум); недоступные пропускаются, после покупки фокус остаётся на строке, если она ещё доступна, иначе уходит на следующую доступную. Кнопка в фокусе пульсирует масштабом (1,00–1,06, ~1,1 Гц), только пока последним использованным устройством был геймпад; с мышью остаётся обычное наведение. A / крест подтверждает, B / круг закрывает меню, Start открывает и закрывает паузу. Встроенная навигация EventSystem у кнопок выключена, чтобы не было двойных нажатий. Кнопка, нажатая в меню, не должна срабатывать в геймплее после закрытия: после закрытия меню игровой ввод остаётся заблокирован ещё один кадр (B закрывает терминал и одновременно привязан к приседу).
* **Настройки (утверждено 07.09):** кнопка «Настройки» в меню паузы открывает подменю: громкость музыки, громкость эффектов (0–100%), чувствительность обзора по горизонтали и по вертикали отдельно (×0,2–×3,0 к базовой), вибрация вкл/выкл, «Назад». Хранятся в `PlayerPrefs` отдельно от сейва (`Settings`), сброс сохранения их не трогает. С геймпада: фокус по строкам, влево-вправо двигает ползунок на 5% и переключает вибрацию, B возвращает в паузу. Вибрация геймпада (утверждено 07.09): короткие импульсы на закрытие полки, смену фокуса и нажатие кнопки в меню (ползунки не вибрируют), готовность способности после отката. Реализация `Rumble` через `Gamepad.SetMotorSpeeds`, выключатель в настройках. На мобильных вибрации нет (решение 07.09: в вебе на iOS недоступна, на Android нужен плагин, не делаем), строка «Вибрация» в настройках скрывается по `Platform.IsMobile`. Сейчас это `Application.isMobilePlatform`, при интеграции SDK Яндекс Игр значение выставляется из данных платформы SDK до открытия настроек. В браузере поддержка вибрации зависит от Gamepad API, проверить в WebGL-сборке. Язык переключается по языку платформы, переключатель в настройках позже.
* **Меню «Управление»:** список действий с глифами клавиатуры/мыши и геймпада, как в референсе. Только просмотр, без переназначения.
* **HUD (постоянно на экране):**
  * Машинок расставлено / всего.
  * Полок закрыто / всего.
  * Коллекционок найдено / 10.
  * Баланс.
* **Панель способностей (утверждено 06.09):** слева внизу три квадратные тёмные плашки с белыми линейными иконками без текста: лупа с машинкой (поиск совпадений), ладони с машинками (автосбор), лупа с машинкой на полке (подсветка стеллажа). Над каждой белая плашка с клавишей: 1/2/3 на клавиатуре, стрелки крестовины на геймпаде (по последнему использованному устройству). Пока способность действует, поверх иконки фиолетовая радиальная заливка, убывающая от 12 часов против часовой; на откате такая же светлая полупрозрачная, иконка приглушена. Некупленные способности не показываются. Активация тратит откат всегда, даже если совпадений в куче нет (решение 06.09). Иконки: `Assets/_Game/Art/UI/`, импорт пунктом меню `SortThem/3d`.
* **Система возврата (Unstuck):** Кнопка в меню или триггер, респаунящий провалившиеся под геометрию машинки в центр зала.

## 6. Мета-активности и эндгейм

* **Слот-машина (CarPot):** в игре есть, не основная механика. Правила и награды не проектируем до готовности ядра, см. бэклог.
* **Скрытые коллекционки (уточнено 07.09):**
  * 10 канистр, спрятанных в труднодоступных местах склада. Сейчас заготовка меша (оливковая канистра с жёлтой крышкой, `Prefabs/Canister.prefab`, меню `SortThem/3e`) и позиции из запечённого разброса тем же фонтаном, что и машинки (меню `SortThem/5b`, отдельно от машинок, раскладку машинок не трогает). На боевом уровне канистры расставляются вручную: позиции в `LevelLayoutData.Collectibles`. Счётчик `X/10` в HUD.
  * Подбор: ЛКМ по канистре под прицелом, контур при наведении как у машинок. Канистра исчезает, звучит свой звук подбора (`GameConfig.CollectibleClip`, сейчас синтезированная заглушка `Audio/collectible_pickup.wav`, два тона), внизу сообщение «Канистра найдена: N/10». Найденные хранятся в сейве битовой маской (32 бита), сброс прогресса возвращает все.
  * Награда за полный сбор не решена, см. бэклог. Черновая идея: уникальная сборная машинка игрока.
* **Касса (утверждено 06.09):** интерактивный объект в зале. Клик по кассе выдаёт небольшую сумму (референс: $1 за клик, всего $10, дальше касса пуста). Пасхалка, на баланс игры не влияет. Реализация после ядра.
* **Радио в основном зале (уточнено 07.09):** тумбочка с радио у южной стены между стеллажами, зеркально терминалу. Контур при наведении, ЛКМ переключает трек по кругу, внизу сообщение «Радио: N/M». Референс держит граммофон в офисе директора, у нас радио в зале; ассет тумбочки/радио заменит кубы.
* **Финал игры:** все машинки расставлены, все полки закрыты. Что происходит в момент 100% — как в референсе, снять, когда дойдём. Офис директора — в бэклоге.

## 7. Платформа и ограничения

* **Целевая платформа первой версии:** веб (WebGL), публикация на Яндекс Играх. Десктопные и мобильные браузеры с первого дня.
* **Будущее:** нативные мобильные сборки. Всё, что зависит от платформы (сохранения, реклама, локализация, ввод), изолируется за интерфейсами, чтобы порт был заменой реализации, а не переписыванием.
* **Следствия WebGL:**
  * Один поток: PhysX и вся логика в главном потоке. Активная физика только в сфере вокруг игрока (раздел 8), запечённый старт обязателен.
  * Draw calls дороже, чем на ПК. Атлас, один материал, GPU Instancing, SRP Batcher — с первой модели.
  * Файловой системы нет: сохранения через `PlayerPrefs` (IndexedDB, лимит 1 МБ) и позже через SDK Яндекс Игр в облако игрока. Формат данных компактный.
  * Событие выхода не гарантировано: сохранение по событиям, таймеру и ручной кнопке, не по `OnApplicationQuit`.
  * Локализация с ключами с первого дня: Яндекс Игры многоязычные.

## 8. Технические требования и оптимизация

* **Начальный разброс (Scatter):**
  * Машинки разлетаются «фонтаном» из центральной точки зала по всему уровню, часть попадает на верх стеллажей. Плотность естественно выше у источника.
  * Разброс запекается в редакторе: инструмент раскидывает, ждёт покоя тел, записывает позиции и повороты в данные уровня. На старте игры машинки спавнятся уже лежащими, `Rigidbody.Sleep()` при спавне. Фриза на старте нет, раскладка детерминирована, спрятанные коллекционки стабильны.
  * Разбрасыватель пишется как рантайм-компонент, а не editor-only скрипт: он же используется для «Перемешать» (см. бэклог).
* **Физика кучи:**
  * Сфера активации вокруг игрока: тела внутри радиуса динамические, вне радиуса спящие тела переводятся в `isKinematic`. Референс делает так же с радиусом около метра. Сфера обрезает каскад пробуждений в плотной куче, где спящие тела будят друг друга через контакт; в однопоточном WebGL без неё игра не пойдёт.
  * Замораживать только спящие тела, иначе брошенная машинка застынет в воздухе. Радиус — параметр конфига, у референса ~1 м, для более живой кучи пробовать 3–4 м.
* **Физические слои (Collision Layers):**
  * Отдельный слой для машинок в куче (`LooseItems`).
  * Отключение физики (`isKinematic = true`) и смена слоя на `StaticPlaced` сразу после фиксации на полке.
* **Рендер:**
  * Все машинки — один атлас текстур и один материал. GPU Instancing включён, SRP Batcher включён. Уникальный материал на модели запрещён: он ломает батчинг.
  * LOD не используется: у low-poly моделей нечего упрощать, узкое место — количество вызовов отрисовки, а не полигоны.
  * Occlusion Culling запекается для уровня, чтобы стеллажи за спиной и за стенами не рисовались. Frustum Culling в Unity работает всегда и не настраивается.
* **Сохранения:**
  * Слой хранения за интерфейсом `ISaveStorage`. Реализации: `PlayerPrefs` (первая, для веба), SDK Яндекс Игр (к публикации), файл (для нативных мобильных). Формат данных один.
  * Что сохраняется: баланс, уровни апгрейдов, найденные коллекционки (битовая маска по индексу), для каждой полки `TargetCarID` и число занятых слотов, для каждого экземпляра машинки статус (на полке / в инвентаре / на полу с позицией и поворотом), слоты инвентаря.
  * У каждого экземпляра стабильный ID из запечённой раскладки. Позиции свободных машинок сохраняются реальные, куча после загрузки не «прыгает» (референс делает так же).
  * Формат компактный: позиции квантованы, порядка 12 байт на машинку, тысяча машинок — около 50–80 КБ.
  * Триггеры: закрытие полки, покупка в терминале, таймер 60 секунд, потеря фокуса вкладкой, ручная кнопка «Сохранить» в меню паузы (референс).
  * При загрузке машинки ниже пола или вне границ уровня возвращаются в центр зала (автоматический Unstuck).
  * **Резервная копия и миграция версий формата (решение 06.09): отложены до этапа интеграции SDK Яндекс Игр.** Сейчас один ключ `PlayerPrefs`, при несовпадении версии сейв отбрасывается. На этапе SDK решить разом: копия предыдущего сейва с откатом при нечитаемом новом, чтение старых версий формата вместо сброса, поведение при конфликте облачного и локального сейва. Урок референса: три волны потери прогресса за десять дней, бэкапы появились последними. Урок наш: баг с пустым инвентарём (см. PROGRESS) стёр прогресс, копия бы спасла.
* **Локализация:** пакет Unity Localization, все строки через ключи (`LocalizedString`), включая названия моделей, категорий и апгрейдов в ScriptableObject. Языки: русский и английский. Язык выбирается автоматически по языку системы (`SystemLocaleSelector`), если его нет среди доступных — английский; при интеграции SDK Яндекс Игр язык платформы выставляется через `LocalizationSettings.SelectedLocale`, остальное не меняется. Таблицы грузятся асинхронно, поэтому весь UI слушает `Loc.Changed` и перечитывает тексты при готовности таблицы и при смене языка: статичные подписи через привязку ключа (`UiRoot.Bind`), вывески стеллажей и ценники по подписке (уточнено 07.09; раньше тексты, построенные до загрузки, застревали на русском запасном значении). Переключатель языка в настройках позже.

## 9. Бэклог (после ядра)
* **Перемешать кучу:** кнопка в меню, запускает разбрасыватель в рантайме за затемнением экрана. Перемешиваются только нерасставленные машинки, полки не трогаются.

* **Награда за 10 коллекционок:** что даёт полный сбор, выбор самого предмета.

* **Офис директора:** отдельная комната с особыми полками. В референсе есть, у нас после ядра.
