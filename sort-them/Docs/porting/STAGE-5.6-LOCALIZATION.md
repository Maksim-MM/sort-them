## Stage 5.6 — Unity Localization: String Tables + фоллбэк + системная локаль

После миграции на TMP (Stage 5.5) — собственно перевод через **Unity Localization** (`com.unity.localization`). Цель: весь видимый игроку текст идёт через String Table; на старте берётся **язык системы**; отсутствующий перевод **откатывается на English** (а не «No translation found»).

> **Когда пропустить:** одна локаль без планов на переводы. Иначе делается даже если переводов пока нет — заливаем только English + фоллбэк: это уже даёт корректный билд и каркас под будущие переводы.

### Инфраструктура (через `LocalizationEditorSettings` / execute_code)
- [ ] `LocalizationSettings` asset, выставить активным (`ActiveLocalizationSettings`).
- [ ] Все целевые `Locale` (en — default). `zh`=Simplified, `zh-Hant`=Traditional — совпасть с маппингом шрифтов в `LocaleFontMapSO`.
- [ ] Один `StringTableCollection` (напр. `Game_Text`) на все локали (среднему проекту хватает одной; крупному — можно бить по доменам).
- [ ] **🔴 Addressables: `BuildAddressablesWithPlayerBuild = BuildWithPlayer`** (+ один `BuildPlayerContent()`). Localization грузит локали/таблицы ТОЛЬКО через Addressables — без собранного контента билд падает на инициализации (в Editor работает, в .exe нет). Симптом: `Invalid path in TextDataProvider … aa/<platform>/settings.json`.

### Конвенция ключей
- [ ] `UI/<Canvas>/<Element>` (Unity покажет деревом); общие переиспользуемые → `UI/Common/*` (OK/Apply/Continue/…). Доменные префиксы для данных: `Product/<enum>`, `StorageType/<enum>`, `Day/<i>`, `Chat/<i>`, `Instruction/<name>`, `Tutorial/<i>`.
- [ ] English-значение **вербатим** (регистр, пунктуация, пробелы, rich-text `<color>`). Остальные локали пусто → фоллбэк.

### Разводка по типам текста
- [ ] **Статичные подписи префабов** → компонент `LocalizeStringEvent` (StringReference=(table,key) + persistent listener `OnUpdateString → TMP_Text.SetText`). Нет `CustomFontSwitcher` (для CJK) — добавить **тем же проходом** (правило: loc и font-switcher всегда парой, см. свип ниже). Вешать на **источник/шаблон** префаба — пропагируется во вложенные инстансы (в т.ч. 2+ уровня).
- [ ] **Текст из кода** → хелпер `Loc.Get(key)` + перегрузка `Loc.Get(key, params object[] args)` (поверх `StringDatabase.GetLocalizedString`; `{0}/{1}` через `String.Format`). Составные строки: локализуем **рамку** с плейсхолдерами, значения — аргументами. Ключ по **стабильному id** (enum/index): `Loc.Get("Product/" + productType)`. **Никогда не выводить enum игроку напрямую**: `$"{productType}"` даёт «PeanutButter» — без перевода и без пробела; грепнуть интерполяции enum'ов в путях к `.text` (UI, мысли/реплики AI).
- [ ] **Сериализованные строковые поля на МНОЖЕСТВЕ префабов** (типа `Item.infoName`/`Item.instruction` на ~100 предметах, выводимые ОДНИМ канвасом): не править сотню префабов. Ключ = префикс + сырая строка (`ItemInstruction/Place items in fridge`), в хелпер добавить `Loc.GetOrRaw(prefix, raw)` — есть entry (`table.SharedData.GetEntry(prefix+raw)`) → перевод, нет → вернуть raw как было. Локализуется ТОЧКА ВЫВОДА (один скрипт), данные не трогаются, незаведённые строки не ломаются.
- [ ] **Компоненты-хинты, которые сами перезаписывают `.text`** (дописывают глиф клавиши) — НЕ вешать на них LocalizeStringEvent (конфликт). Доработать сам компонент: добавить loc-ключ, строить текст из `Loc.Get(key)` + глиф, **перестраивать при `SelectedLocaleChanged`** (строить заново, не `+=`). Один владелец текста на TMP — если на TMP были И ShowKeyBinding-подобный, И LocalizeStringEvent, убрать лишний.
- [ ] **Незаполняемые плейсхолдеры шаблонов**: карточка с N пред-размещёнными строками, данных меньше — лишние строки светят дефолтным текстом шаблона («Company / Product»). Не переводить заглушку — после заполнения **выключать лишние строки кодом** (`for i=count..rows: row.SetActive(false)`).

### 🔴 Типовые рантайм-косяки (каждый словлен на практике)
- [ ] **`Loc.Get` в `OnValidate()`** — editor-only, в рантайме/билде НЕ выполняется, текст остаётся дефолтным. Грепнуть все `OnValidate` на Loc-вызовы → перенести в `OnEnable`/рантайм-метод.
- [ ] **Гонка локали на старте**: менеджер локали применяет сохранённый язык в корутине (после `LocalizationSettings.InitializationOperation`), а `Start()` сценовых объектов уже запёк `Loc.Get`-тексты на системной/default локали (симптом: единичные тексты «не на том» языке после загрузки). ПРАВИЛО: код, ставящий Loc-текст в `Awake/Start` при загрузке сцены, обязан либо подписаться на `SelectedLocaleChanged` и перечитать, либо ставить текст лениво при показе. `LocalizeStringEvent`-статике гонка не страшна (обновляется сам).
- [ ] **Объекты SDK/плагинов со слэшем в ИМЕНИ** (`(Apply) Button / Upscale SDK`): `transform.Find("path/to")` их НЕ находит — свипы молча пропускают узлы, остаются нелокализованные геймпад-капшены. Для таких — ручной обход детей с сравнением по имени.

### Фоллбэк на English (🔴 критично)
- [ ] `LocalizationSettings.StringDatabase.UseFallback = true` **И** на каждую не-default локаль метадата `UnityEngine.Localization.Metadata.FallbackLocale{ Locale = en }`. Только при ОБОИХ условиях отсутствующий перевод показывает English. Один `UseFallback` без метадаты (или наоборот) НЕ работает — типовой затык: «No translation found for '<key>'».
- [ ] Диагностика: «No translation found» в рантайме = поле ПОДКЛЮЧЕНО к локали (и фоллбэк выключен). После включения фоллбэка везде English — это норма (переводов нет).

### Стартовая локаль
- [ ] Стартовые селекторы: `CommandLine → System → Specific(en)`. `SystemLocaleSelector` обязателен для консолей (первый запуск = язык системы; матчит по цепочке культур: zh-CN→zh-Hans→zh, pt-BR→pt-BR). Безопасно только с фоллбэком (непереведённое = English). Если на время ревью форсили English (убирали SystemLocaleSelector) — НЕ забыть вернуть после заливки переводов.
- [ ] Persist выбора (свой `LocaleManager` + `Saves["LocaleCode"]`, строковый код надёжнее индекса); экран смены языка — отдельно (часто в Splash/бутстрапе до геймплея).
- [ ] Честно проверить автоопределение можно только на чистом сейве при не-английской системе (devkit / смена языка ОС) — в Editor SystemLocaleSelector берёт язык ОС разработчика.

### Перевод (заливка всех локалей)
- [ ] **Сначала терминологический док** (`LOCALIZATION_TERMS.md` в этой папке, `porting/`): обязательная терминология платформодержателя (TRM/directional terminology — Vibration / Light Bar / Controller и т.п., таблица точных переводов на все языки) + решения по тону. Правило: если термин из дока встречается в игровом тексте — перевод берётся ДОСЛОВНО оттуда.
- [ ] Зафиксировать **тон обращения** до перевода (казуалкам — неформальный: ты/du/tu) — иначе переделывать все императивы туториала/подсказок.
- [ ] Пайплайн заливки: экспорт en → TSV `key\tvalue` (экранировать `\n`/`\t`!) → перевод → импорт execute_code'ом (`table.AddEntry(key, value)` + `SetDirty(table)` + `SaveAssets`), отчёт `set/unknown` на локаль — `unknown>0` значит ключи разъехались. Сохранять при переводе: плейсхолдеры `{0}/{1}`, rich-text `<color>`-теги (могут переезжать вместе со словом — ja «<color>{0}</color>日目»), хвостовые `\n`, намеренные «провалы» под подстановку.
- [ ] Машинный перевод — ок как первый проход, но для шиппинга флагнуть LQA носителями (юмор/реплики страдают первыми).

### Live-refresh
- [ ] Императивные `Loc.Get`-тексты ставятся ОДИН раз и не меняются при смене языка «на лету». Если язык выбирается на старте/в Splash (геймплей грузится заново) — этого достаточно. Нужна смена без перезагрузки — подписать контроллер на `SelectedLocaleChanged` и перечитать `Loc.Get`.

### Наборы символов и атласы шрифтов (CJK + кириллица/диакритика)
После заливки переводов статическим TMP-атласам нужны все использованные символы — иначе квадраты/пропуски. **Базовый латинский шрифт — такой же риск, как CJK**: в его атласе запросто нет кириллицы/ş/ł/ą — проверять, не предполагать.
- [ ] **Извлечь наборы символов из String Table** (execute_code): для каждой CJK-локали собрать уникальные символы из всех значений таблицы + полный printable ASCII (цифры/латиница/пунктуация в смешанных строках) → txt-файл (например `FontAtlasChars/atlas_chars_<locale>.txt`, вне `Assets/`). Отдельный объединённый набор по всем латиница/кириллица-локалям — для базового шрифта.
- [ ] **Первичная сборка атласа** — Font Asset Creator, txt-набор в Custom Characters (выбор размера атласа/point size/padding — руками).
- [ ] **Доливка новых символов** (изменились переводы) — БЕЗ пересборки, скриптом: `SerializedObject.FindProperty("m_SourceFontFile")` = TTF (сеттер свойства read-only!) → `atlasPopulationMode = Dynamic` → `TryAddCharacters(missing, out failed)` → обратно `Static` → `m_SourceFontFile = null` (иначе TTF утянется в билд) → `SetDirty(fontAsset + все atlasTextures)` + `SaveAssets`. Настройки и существующая упаковка атласа не трогаются. Требование: исходный TTF лежит в проекте (GUID — в `creationSettings.sourceFontFileGUID`).
- [ ] **🔴 `TryAddCharacters` вернул `failed` — это ДВЕ разные причины**: (а) глифа нет в TTF, (б) **в атласе кончилось место**. Различать проверкой TTF напрямую: `FontEngine.LoadFontFace(ttf)` + `TryGetGlyphIndex(unicode)`. Если глиф в TTF есть → место: включить `m_IsMultiAtlasTexturesEnabled = true` (вторая текстура) и повторить. Минус multi-atlas — вторая текстура почти пустая (память) → при случае пересобрать одним атласом с меньшим point size. Легитимный failed — кросс-скрипт символы (хангыль в японском наборе из-за общих строк) — рендерятся другим шрифтом, игнорировать.
- [ ] После каждого изменения переводов — перегенерировать txt-наборы и долить ВСЕ атласы (включая базовый), сверить точечно `characterLookupTable.ContainsKey` по новым символам.

### Что НЕ локализовать
- Бренды/имена собственные (компании), маркетинговые имена (названия цветов краски), чистые числа/цены/таймеры, буквы клавиш (W/A/S/D).

### Аудит покрытия (не доверять одному свипу — нужны ЧЕТЫРЕ)
Один проход не находит всё; реально потребовались все четыре + прогон игры на CJK-локали со скриншотами от тестировщика:
- [ ] **Свип 1 — статичный по префабам**: все TMP c НЕпустым буквенным текстом БЕЗ `LocalizeStringEvent` и без хинт-компонента (ShowKeyBinding-подобных). Фильтровать числа/валюту. Это базовый проход.
- [ ] **Свип 2 — запущенная сцена**: `Resources.FindObjectsOfTypeAll<TMP_Text>()` + фильтр `gameObject.scene.IsValid()`. Ловит рантайм-инстансы (карточки товаров, пред-размещённые карточки Manage), которых нет в статичном свипе.
- [ ] **Свип 3 — «loc есть, font-switcher нет»**: все TMP, где стоит `LocalizeStringEvent`/хинт-компонент, но НЕТ `CustomFontSwitcher` → на CJK будут квадраты при правильном переводе. (Главный источник — узлы со слэшем в имени, см. рантайм-косяки.)
- [ ] **Свип 4 — сериализованные строки и код**: дамп всех значений строковых `[SerializeField]`-полей, попадающих в `.text` (infoName/instruction/описания), по всем префабам; greps: `OnValidate`+Loc, `$"{`-интерполяции enum, литералы в `DOFire*(…"text")`.
- [ ] Пред-размещённые карточки лежат в `*_Panel`-префабах (не в шаблоне карточки); шапки/Owned/Purchase с шаблона в них пропагируются, а уникальный per-instance текст (заголовки секций/сервисов, имена мебели) — вешать/оверрайдить на каждом инстансе в панели. Это ПОВТОРЯЮЩИЙСЯ паттерн пропусков — проверять каждую `*_Panel`.

### Экран выбора языка (Splash/бутстрап)
- [ ] Имена языков в списке — **нативные** (Русский, 日本語, Deutsch), стандарт индустрии; не переводить список. Ключи `Language/<code>` с ОДИНАКОВЫМ значением во всех локалях — так символы имён автоматически попадают в пайплайн наборов/атласов.
- [ ] Шрифт каждой строки — по коду ЕЁ локали (`LocaleFontMapSO.GetFont(code)`), не по текущей (иначе 日本語 квадратами при английском UI).
- [ ] **Живой предпросмотр**: выделение строки = `LocalizationSettings.SelectedLocale = locale` (вся статика обновится сама); Apply → persist через LocaleManager; Cancel → вернуть исходную локаль.
- [ ] Геймпад: открытие по hotkey (Start), своя Layer-изоляция поверх остального UI, dpad up/down + глифы, Apply/Cancel — семантические SDK-кнопки (ремап по платформе).
- [ ] Если на сцене есть гейт «Press Any Button» — заглушить его на время работы панели (флаг IsOpen + пара кадров после закрытия + игнор hotkey-кнопки), иначе открытие панели стартует загрузку.

### Чистка старого стека локализации
- [ ] Был свой JSON/SO-стек — удалить после миграции: сперва GUID-grep по сценам/префабам (нет ссылок) + вычистить мёртвые код-ссылки (иначе не скомпилится), потом удалить скрипты+ассеты+JSON.

### Verification
- [ ] `refresh_unity`+`read_console` — ноль ошибок; `GetLocalizedString` по выборке ключей возвращает English.
- [ ] До переводов: не-en локаль → весь UI English через фоллбэк, без «No translation found». Тестовый перевод на 1 локаль (10-15 ключей) → поля переводятся (доказывает подключение ДО массовой заливки).
- [ ] После переводов: полный прогон игры на CJK-локали (магазин, Manage-вкладки, касса, туториал, подсказки у предметов, мысли AI) — искать английские остатки и квадраты. Скриншоты пропусков → точечные фиксы (обычно 2-4 итерации).
- [ ] Смена языка через UI: применился + сохранился + восстановился после рестарта; Cancel откатывает.
- [ ] Билд: Addressables-контент в плеере, инициализация локализации без краша.
