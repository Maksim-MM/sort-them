# Порт Sort Them на консоли — лог

> Лог порта по этому проекту. Общий пайплайн — `PORTING_PIPELINE.md` в этой папке, канон SDK — `UPSCALE_SDK.md`. Журнал разработки самой игры — корневой `PROGRESS.md`, сюда только порт.

## Решения (23.09)

- **Платформы:** ПК (клавиатура+мышь, геймпад), консоли через Upscale SDK, WebGL (Яндекс Игры) остаётся целевой платформой. Точный список консолей: Switch 1 (девкит есть); PS5/PS4/Xbox — уточнить у пользователя.
- **Одна ветка, один код.** Платформенные различия — через asmdef с `includePlatforms`, `#if` только в фабрике реализаций, Build Profiles на платформу. Долгоживущих платформенных веток не заводим.
- **WebGL не выкидывается** (отклонение от пайплайна, где мобильный/веб-код удаляется). Тач-схема остаётся под `Platform.IsMobile`; плагин Яндекса (PluginYG2) пойдёт в отдельный asmdef `includePlatforms: ["WebGL"]`, на консольных сборках его кода не будет. Сетевых обращений, рекламы, покупок, аналитики в проекте нет — Stage 1 практически пустой.
- **Управление на ПК и консолях — через SDK** (`PlayerInputActionSet` поверх `InputActionsSet`, UI-слои SDK). Игра делалась под ПК и геймпад с нуля.
- **Пока не делаем:** трофеи/ачивменты, активности PS5, Light Bar (решение пользователя 23.09).
- **Глифы:** готовые наборы из `Assets/UpscaleSDK/Extras/Glyphs/`, SDK выбирает набор по платформе сам. Подтверждение/отмена в подсказках — только через семантические `GamepadAction.Apply/Cancel`, не позицией кнопки (см. `GOTCHAS.md`, Switch).
- **Лог порта** — этот файл, корневой `PROGRESS.md` не трогаем (там журнал игры).

## Правила параллельной работы: веб и консоли (24.09, обязательно при каждой сессии)

Веб начат раньше плана: Switch заблокирован (девкит занят, срок неизвестен), решение пользователя 24.09. Работа идёт попеременно, вернуться к Switch можно в любой момент, поэтому:

1. **Каждый коммит собирается под Switch.** Сервер собирает из git. Веб-работа делится на маленькие законченные шаги; после каждого — компиляция без ошибок и явное «можно коммитить». Незаконченный веб в рабочем дереве не должен ломать консольную сборку.
2. **Веб-код изолирован:** отдельный asmdef с `includePlatforms: ["WebGL"]` или `#if UNITY_WEBGL`. Компилятор консоли его не видит. Плагин Яндекса только внутри этой сборки.
3. **Общее поведение не меняется ради веба.** Если веб требует правки общего кода (сейвы, ввод, UI), по умолчанию остаётся текущее консольное поведение, веб подключается отдельной реализацией.
4. **Различия контента — при сборке, не в ветке:** Build Profiles, отдельный конфиг под веб (меньше музыки/звуков, только en/ru), подставляется `BuildTool`. Сцены и таблицы локализации общие.
5. **Addressables при смене платформы:** кэш `[BuildTarget]` (см. `OPTIMIZATION.md`, 23.09). Для веба защищает `BuildTool.EnsureWebGLTarget()`; если обе платформы начнут собираться на одной машине в одной сессии редактора — обобщить на Switch.

## Особенности проекта

- UI строится кодом (`UiFactory`, `UiRoot`), не префабами: слои SDK (`Layer`, `ActionButtonElement`, `LayerNavigator`) прикручиваются в коде-генераторе; ловушки префабов из `GOTCHAS.md` не актуальны.
- Одна сцена `Main`; `Editor/BuildTool.cs` собирает по `Paths.MainScene`. Bootstrap-сцена SDK `UPSBootstrap` должна стать сценой 0 — добавить в Build Settings и в `BuildTool`. `SceneManager.LoadScene(int)` в коде игры: проверить grep'ом после добавления сцены.
- `Resources/` в `_Game` нет; локализация через Addressables.
- Под валидатор SDK: `companyName` = `DefaultCompany` → нужен ровно `Upscale Studio`; `bundleVersion` 0.1.0 подходит; заставка Unity включена (предупреждение валидатора, для консолей выключить).
- На машине пользователя установлены модули Android, WebGL, Windows, Mac. Консольные модули Unity — с порталов платформодержателей; до их появления вся интеграция проверяется на Desktop-платформе SDK.
- `Editor/BuildTool.cs` уже содержит `EnsureWebGLTarget()` (сброс кэша Addressables `[BuildTarget]`) — при появлении консольных сборок обобщить на любую целевую платформу.

## Switch: вылет через 2–3 минуты — ошибка SDK в секции ExitRequest (25.09)

- Дамп (`dump-cars.txt`, 8 падений подряд): `Assertion failure: g_EnableHandlingForExitRequestCount > 0 … LeaveExitRequestHandlingSection (oe_OperationStateControlApis.cpp:336)`, затем `AbortObserver` и снимок `.nxdmp`. Падает на ~4200-м кадре (≈ 2,3 мин при 30 FPS).
- Причина — SDK Upscale v2.1: `SwitchPlatform.Initialize` один раз вызывает `EnterExitRequestHandlingSection`, а `SwitchFileSystem.Write` на **каждой** записи сейва вызывает `LeaveExitRequestHandlingSection` в `finally` без парного Enter. Первая запись: 1 → 0, вторая: 0 → assert → abort.
- Правка в SDK (локально, канон SDK больше не байт в байт): в `SwitchFileSystem.Write` перед `try` добавлен `EnterExitRequestHandlingSection()` под `#if UNITY_SWITCH`. Счётчик вложенный: запись 1→2→1, при `ExitRequest` платформа сохраняет (2→1) и выходит (1→0), система закрывает игру. Проверить на девките; сообщить авторам SDK.
- Отдельно в том же логе: с ~55-й секунды игры сериями по 3 каждые ~4–5 с идёт `Unloading 0 unused Assets … Total ≈ 110 ms (MarkObjects ≈ 93 ms)` при переключении `Serialized files now loaded` 4↔5 — заметные подвисания. В коде игры и в рантайм-коде пакетов `UnloadUnusedAssets` не вызывается (только `Fonts.Apply` при смене языка); в редакторе не воспроизводится. Источник не найден — нужен профайлер Development-сборки на девките в момент спайка.
- Также в SDK лежит незакоммиченная правка `NewUnityInputProvider.GetGamepadType` (null в `description`, см. GOTCHAS).

## Частота записи сейва на консолях (25.09)

- Было: каждый `SaveService.SaveNow` сразу писал файл (`UpscaleSaveStorage.Save` → `prefs.TrySave()`): автосейв игры каждые 60 с, плюс закрытие полки, покупка апгрейда, чертёж, коллекционка, кнопка «Сохранить» (можно спамить), шаги обучения, потеря фокуса/пауза приложения; поверх — автосейв SDK каждые 300 с (пишет без проверки изменений).
- Решение пользователя: Switch — не чаще раза в 60 с (риск на сертификации); PS/Xbox — 30 с (так проходил сертификацию раньше); ПК/веб — без ограничения.
- Сделано: `ISaveStorage` = `Stage(data)` (данные в память SDK) + `Commit()` (запись файла). `SaveService.SaveNow(reason, force)`: всегда `Stage`, если данные отличаются от последних отданных; `Commit` — только если прошло `MinCommitInterval` с прошлой записи или `force`; иначе флаг «есть незаписанное», дописывается из `Tick` по `Time.unscaledTime`. Одинаковые данные не пишутся вовсе (и принудительно тоже). Интервалы: `GameConfig.SaveMinIntervalSwitch = 60`, `SaveMinIntervalConsole = 30` (`#if UNITY_SWITCH` / `UNITY_PS4 || UNITY_PS5 || UNITY_GAMECORE || UNITY_XBOXONE`), иначе 0. `force` — потеря фокуса и пауза приложения. `Settings.Store` вызывает `Save.MarkDirty()`, чтобы настройки попали в ближайшую запись.
- Автосейв SDK выключен (`Resources/UpscaleSDK/SaveSettings.asset`, `EnableAutosaves: 0`): он писал без проверки изменений и мог попасть в окно 60 с после нашей записи. Автосейв теперь только игровой (60 с).
- Выход через HOME: SDK по `ExitRequest` пишет то, что лежит в памяти, — там всегда последний `Stage`. Риск: при выдёргивании питания теряется до 60 с (Switch) / 30 с прогресса.
- Проверено в редакторе (интервал 0): первое сохранение — запись; повтор без изменений — без записи; принудительное без изменений — без записи; после `MarkDirty` — запись. Сам интервал проверяется только на консоли.
- Чит `CheatFill.FillAllButOne` (L3 в настройках, только Editor/Development) раскладывает почти все машинки за кадр: каждая закрытая полка вызывала `SaveNow("shelf closed")`, открытые чертежи — `SaveNow("blueprint unlocked")`, в конце `SaveNow("cheat fill")` — сотня с лишним сохранений в одном кадре. На Switch со старой логикой это та же ошибка SDK (вторая запись → abort) сразу после чита; на ПК/вебе — сотня записей файла подряд и сотня сериализаций 3000 машинок.
- Добавлено: обычный `SaveNow` только ставит запрос, сохранение выполняется один раз в `SaveService.Tick` следующего кадра (одна сериализация, одна проверка изменений); сразу — только `force` (потеря фокуса, пауза приложения). Запрос во время `Shuffling` ждёт окончания перемешивания. `ClearSave` снимает ожидающие запросы и флаг незаписанного.
- Проверено в Play: 150 `SaveNow` в кадре — < 1 мс, записей в кадре 0, в следующем кадре одно сохранение (данные совпали с записанными — запись пропущена). Сейв редактора перед тестом скопирован в `Tools/backups/SortThem_save_before_cheat_2026-09-25_14-23-44.txt` (304/305 полок, чит новых не закрыл).

## Освещение стеллажей перезапечено (27.09)

Симптом: на части полок и стоек (~10–15 %) тёплые оранжевые полосы по кромкам, видно в редакторе, значит и на Switch. Static batching ни при чём (кадры со склейкой и без совпадали до пикселя).

Деталям стеллажей назначен `Data/Config/RackLightmap.giparams` (8 образцов на тексел).
- Пробовали и откатили: `pushoff` 5 мм (не помог); стеллажи на пробах света вместо карты (детали целиком светятся оранжевым — пробы на 4 м у ламп).
- Карт освещения теперь 7 (одна 2048², шесть мелких; разные Lightmap Parameters → разные карты), веб-сборка +6 МБ. Сжатие High Quality выставлено всем картам вручную — после каждого перезапекания повторять (см. GOTCHAS). Стеллажи стали немного светлее и теплее: пятна от ламп на полках больше не размываются. ## Титул зависал на Яндексе: освобождённый хэндл инициализации локализации (30.09)

- Симптом «плавающий»: музыка титула играет, надписи нет, панель Яндекса — «"ready" called on timeout». Воспроизведено в активной вкладке Chrome (после `osascript activate`), то есть не троттлинг.
- Причина: `LocalizationSettings.SetSelectedLocale` → `SendLocaleChangedEvents` **освобождает** `m_InitializingOperationHandle` (`SafeRelease`) и создаёт новую операцию. `TitleScreen.InitLocalization` (и `GameManager.InitLocalization`) держали захваченный ранее хэндл `op` и опрашивали `op.IsDone` → Addressables бросает «Attempting to use an invalid operation handle», корутина умирает, `_ready` не ставится. Триггер — `WebLocales.Filter` в колбэке `InitializationOperation.Completed` ставил `SelectedLocale` по языку площадки, если он отличался от выбранного системным селектором (браузер en, площадка ru). Плавает от порядка: успел ли `Completed` сработать до захвата хэндла титулом. До 29.09 смена локали в `Filter` была только при языке вне списка девяти, поэтому почти не проявлялось.
- Правка: (а) `WebLocales` — язык площадки через `IStartupLocaleSelector` (`PlatformSelector`, вставлен первым в `LocalizationSettings.StartupLocaleSelectors` до старта инициализации; фолбэк ru/en по системному языку там же), локаль выбирается один раз при инициализации, после `Completed` только фильтрация списка, `SelectedLocale` больше не трогается; (б) общий код: `TitleScreen`/`GameManager` перечитывают `LocalizationSettings.InitializationOperation` на каждом опросе вместо захваченного хэндла — смена локали кем угодно во время ожидания больше не роняет корутину. На консолях (б) безобидна.
- Проверено на Яндексе (новый архив, активная вкладка): `lang=ru` — «ready» через 3,6 с, «Нажми любую клавишу»; `lang=en` — 3,0 с, «Press Any Key»; `lang=de` — 3,4 с, «Beliebige Taste drücken»; незаявленные: `lang=ja` → английский, `lang=uk` → русский (резерв), оба ~3 с. Требование Яндекса 2.14 (автоопределение языка при запуске через `i18n.lang`, отдельная проверка каждого заявленного языка) выполняется; в черновике заявлять ровно 9 языков веб-сборки.

## Коробки с запчастями просыпаются по физике (01.10)

- **Было:** `SpawnCollectibles` ставил Rigidbody коробки `isKinematic = true`, а `SettleCollectibles` опускал её на опору только при старте, загрузке и перемешивании. Взял машинку из-под коробки — коробка висит в воздухе.
- **Стало:** `Collectible` хранит `Body`/`CalmSince`; `PhysicsActivation.Tick(List<Collectible>, …)` будит коробки в том же радиусе, что и машинки (`ActivationRadius` / `MobileActivationRadius`), и замораживает обратно, когда уснули или спокойны `FreezeDelay`. `GameManager.WakeCollectiblesNear` (радиус 1 м) вызывается из `Inventory.Add` по позиции взятой машинки — дальность взаимодействия (2,2 м) больше радиуса активации (1,5 м), без этого коробка могла остаться висеть. На время `ShuffleLoose` коробки снова kinematic, потом `SettleCollectibles` как раньше. Позиции коробок по-прежнему не сохраняются — при загрузке берутся из раскладки и опускаются `SettleCollectibles`.
- Проверено в Play (Main): машинка из-под `Collectible_5` взята в 14 м от игрока — коробка упала 0,519 → 0,250 и заморозилась; игрок в 1,3 м от `Collectible_19` — коробка проснулась и осталась лежать. Ошибок в консоли нет. Бэкап сейва до теста: `Tools/save_backups/SortThem_2026-10-01_before_crates.txt`.
