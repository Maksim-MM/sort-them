# Console Porting Pipeline — индекс

> 🆕 **Впервые здесь?** Начни с `README.md` — он объясняет связку «ИИ + эта папка» и рабочий процесс. Этот файл — технический индекс/маршрутизатор.

Универсальный пайплайн портирования мобильных/веб-игр на консоли (PS4/PS5, Xbox, Switch) **с сохранением (или добавлением с нуля) PC-управления**. В новый проект копируется **папка `porting/` целиком**.

**Целевые платформы по умолчанию:** PC (клавиатура+мышь, геймпад) + консоли. Мобильные/веб платформы исключаются из сборки — связанный код можно удалять без условий (`isMobilePlatform` для UI-логики, touch-handlers и т.д.).

> ⚠️ **Это НЕ жёсткая последовательность, а карта-направление.** Игры разные — какие-то этапы не нужны вовсе и их **пропускают**: нет рекламы → нечего удалять; нет IAP → нечего конвертировать; нет Legacy `UI.Text` → нет миграции на TMP; уже New Input System с геймпад-биндингами → меньше работы; не планируется локализация → Stage 5.5/5.6 не нужны.
>
> **Правило:** не выполняй этап вслепую только потому, что он тут перечислен. Сначала на Stage 0 составь **план порта под конкретный проект**, определи, какие этапы применимы, и **согласуй каждый крупный этап с разработчиком отдельно** — особенно решения, меняющие игру/баланс/контент: что выпиливаем из SDK, как поступаем с рекламой и IAP, нужна ли локализация и TMP, маппинг кнопок по слоям. Этапы можно делать не по порядку и частично.

> **Маркер примеров:** строки вида `> 📍 Пример (этот проект):` в файлах стадий — привязка к проекту, который писал доку. В новом проекте у этих имён аналога не будет — найди свой эквивалент; правило при этом универсально.

## Правило чтения (экономия контекста)

**Не читай все файлы стадий подряд.** Прочитай этот индекс, по таблице маршрутизации определи нужный файл — и читай только его. Дополнительно:

- `GOTCHAS.md` — **перед любой работой с префабами/сценами через Unity MCP**, на любой стадии.
- `UPSCALE_SDK.md` — при работе с геймпадом/сейвами/глифами/вибрацией/трофеями. **Baseline SDK = v2.1** (нумерация внутренняя; дельта v2→v2.1 — в шапке `UPSCALE_SDK.md`: rename `BaseInputActionSet`→`BaseGamepadActionSet`, клавиатура+мышь, device-aware глифы, новые UI-компоненты, автодиалоги ошибок сейвов PS). `UPSCALE_SDK.md` — выверенный канон (сверен с живым SDK); сырьё вендор-доки — `UPSCALE_SDK_V2_SOURCE.md` (соответствует v2.0 — сайт вендора не обновлён). `STAGE-2-5` (геймпад/ввод/UI/слои/глифы) и `STAGE-6` (консольный SDK: трофеи/активности/сейвы/вибрация) — актуализированы под v2.1.
- `MCP_REFERENCE.md` — краткий справочник MCP-тулов.

## Стартовый протокол нового проекта

Когда прилетел новый проект на порт:

0. **Скопировать папку `porting/`** в корень проекта (она не в git — держится локально и переносится руками).
1. **Сначала собрать проект, не анализировать.** Открыть в Unity Hub / Rider, дать импортнуться, выставить требуемую версию Unity, починить ошибки компиляции (битые рефы, API-брейки после апа версии, отсутствующие пакеты). Это обычная работа в **чистом чате** — порт-доки читать НЕ нужно, порт-специфики тут нет.
   - **Почему первым:** `/unity-analyze` и весь дальнейший порт идут через Unity MCP (`manage_scene`/`get_hierarchy`/`read_console`), а MCP даёт осмысленный результат только на Editor **без ошибок компиляции** — по сломанному проекту сцены не грузятся, анализ мусорный.
2. **Когда Editor чистый и MCP отвечает** → `/unity-analyze` (Stage 0): генерит `CLAUDE.md` (с порт-станзой) + `ARCHITECTURE.md` + заготовку `PROGRESS.md`, проверяет наличие `porting/`.
3. Дальше — по фазам, каждая в своём чате (см. «Протокол сессий» ниже).

> **`/init` для Unity-проектов не использовать** — `/unity-analyze` его перекрывает (Unity-aware: читает сцены через MCP, генерит сразу 3 дока + порт-бутстрап). Запуск обоих создаёт конфликтующие `CLAUDE.md`.

## Протокол сессий (новый чат на фазу)

Новая фаза порта = новый чат (компакт теряет детали; чистый старт дешевле и надёжнее):

1. **Старт сессии:** `CLAUDE.md` проекта (станза с триггер-словами) → этот индекс → файл текущей стадии → `PROGRESS.md` (что уже сделано).
2. **Конец фазы:** обновить `PROGRESS.md` (статус, решения, отклонения от пайплайна), новые подводные камни — в файл стадии + строку в таблицу ниже.

### Указатель подводных камней (для маршрутизации багов)

**`GOTCHAS.md` (cross-stage, префабы/MCP):** MCP + Prefab Stage — молчаливые save-ошибки · "script does not derive from MonoBehaviour" (закомментированный `.cs` с живым `.meta`) · двойные nested UI-элементы — править исходный префаб · Nested Prefab AddedGameObject override · смена `companyName` теряет `PlayerPrefs`, `defaults write` при живом редакторе бесполезен · Addressables кэширует `[BuildTarget]` между сборками под разные платформы (каталог с чужим путём) · SDK `GetGamepadType()` NRE на паде без description (виртуальные/экзотические HID) · TMP-атлас из текста таблиц: `UpperCase` применяется при рендере — набор символов в обоих регистрах · пересборка TMP-атласа на месте не обновляет `_TextureWidth/_TextureHeight` материала · новый `.cs` импортирован, но не попал в `.rsp` сборки — переименовать файл · выключение группы Addressables на время сборки сохраняется на диск — восстанавливать с сохранением.

**Stage 1:** типовая карта rewarded-точек · варианты замены рекламы (таблица) · поиск ad-кнопок в UI · реклама на 3D-объектах через World-Space Canvas · параллельные системы (rewarded + IAP) на одну механику · Privacy Policy / Rate Us / GDPR · обязательный sweep broken-script компонентов · sanity checklist.

**Stage 5.5:** 4 класса поломок при миграции · процедура L0–L4 (идемпотентно) · nested-prefab stripped-ссылки, неполный каскад · **порядок L1→L2 нерушим (смена типа поля обнуляет ссылку сразу; восстановление — парсинг base-YAML, в т.ч. stripped-блоков)** · `[RequireComponent(typeof(Text))]` молча ломает конвертацию (`AddComponent` → null) · `Outline`/`Shadow` мешают удалить Text и на TMP не работают (общие материалы, не per-object) · ссылки, сломанные ДО миграции, маскируются под регрессии (сверять base-YAML per-component) · искать существующие TMP-шрифты (`t:TMP_FontAsset`), не плодить дубликаты атласов · **TMP не наследует OS-фоллбэк → CJK/Thai/Arabic ломаются, если игра уже локализована** · итоговая проверка в Play через `FindObjectsOfTypeAll<TMP_Text>`.

**Stage 5.6:** типовые рантайм-косяки · фоллбэк на English (критично) · стартовая локаль · CJK + кириллица атласы · что НЕ локализовать · аудит покрытия — ЧЕТЫРЕ свипа · экран выбора языка · чистка старого стека.

**Stage 6:** generic-паттерн трофеев · паттерн миграции сохранений · инвентарь `PlayerPrefs` грепать по всему `Assets/` (живые донорские модули вне `Scripts/`; мёртвые остатки — удалять, не мигрировать; PlayerPrefs-вьюеры после миграции слепнут) · **сейвы SDK поднимаются сами (`RuntimeBootstrap`, BeforeSceneLoad) — бутстрап-сцена нужна для лого/гейта, но `Prefs` до `Initialize()` даёт NRE** · `Saver` при загрузке заменяет словарь целиком → ранние `Set*` стираются молча · гейт готовности вешать на существующий загрузочный экран / «Press any button» (снимает нужду в гардах по всему геймплею) · триггер сейва централизовать в один объект (иначе N синхронных записей на выход); переименование платформенного триггера — с сохранением GUID в `.meta` + `m_Name` в сцене · `OnContextRequestSave` до игрового кода не доведён (`_platform` приватный) · ключи настроек сверять между UI и сервисами (`Setting_Vibration` int vs `Settings.Vibration` bool) · `XboxContainerName` = имя файла сейва на всех платформах · активности PS5 не стартуют по умолчанию — фикс `IsUserRegistered` (race с UDS-регистрацией) · `.asmdef` изоляция.

## Поддержка пайплайна

- **Стиль кода: не добавлять комментарии в код без явной просьбы** (инлайн `// ...`, XML-доки и т.п.). Если комментарий где-то нужен — разработчик попросит отдельно. Примеры/пояснения держим в доках, не в коде.
- Новый подводный камень → в файл своей стадии + **одна строка** в указатель выше. Контент стадий в индекс не дублировать.
- Generic-правила — в файлы стадий; project-специфика — `> 📍 Пример (этот проект):` или `PROGRESS.md`.
- Скиллы Claude Code: `/unity-analyze` (анализ проекта + бутстрап порт-доков), `/unity-mcp-skill` (оркестрация Unity через MCP). Повторяющиеся задачи выноси в скиллы.
