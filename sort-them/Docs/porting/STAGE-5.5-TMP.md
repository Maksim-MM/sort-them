## Stage 5.5 — Локализация: Legacy Text → TMP (reference-preserving)

Нужна, когда под локализацию (особенно со сменой шрифтов под CJK-иероглифы) требуется перевести проект с Legacy `UnityEngine.UI.Text` на TMP. Компоненты смены шрифта (`CustomFontSwitcher`/`LocaleFontMapSO`) — **TMP-only**, поэтому весь видимый игроку текст должен стать `TextMeshProUGUI`. Это **подготовка** к штатной Unity Localization (String Tables — отдельный этап после).

> ⏭️ **Когда ПРОПУСКАТЬ этот этап целиком:**
> - В проекте **нет** Legacy `UnityEngine.UI.Text` (всё уже на TMP) — проверь: `grep -rl "UnityEngine.UI.Text\b" Assets/Scripts` пусто И в префабах/сценах нет компонентов Text. Тогда мигрировать нечего.
> - **Локализация не планируется** (одна локаль, без смены шрифтов). Legacy Text прекрасно работает для одного языка — миграция ради неё не нужна.
> - Локализация **только латиница/кириллица, без CJK**, и менять рендер-стек не хочется: Unity Localization (`LocalizeStringEvent`) умеет писать и в Legacy `Text`, и в `TMP_Text` — подмена строк работает на обоих. Профит TMP здесь маргинальный (в основном SDF-чёткость и единый стек). Решение — **согласовать с разработчиком**, churn миграции реальный.
>
> Основной профит TMP — под **консоли + CJK**: контроль над атласом/памятью шрифтов, SDF-чёткость при масштабе, переиспользование готового TMP-свитчера шрифтов. Если этих факторов нет — взвесь, нужен ли этап вообще.

> ⚠️ **ГЛАВНОЕ ПРАВИЛО.** Миграция Text→TMP — это **не «сменить тип компонента»**, а «**перенести компонент + ВСЕ его входящие ссылки + ВСЕ значения настроек**». Источник истины — **чистый pre-migration git-коммит**, а не живое (возможно уже испорченное) дерево. Наивная замена компонента молча обнуляет каждую сериализованную ссылку на этот текст по всему проекту, и чинить приходится постфактум по всей игре — это и есть типовой провал, ради которого написана эта секция.

### Почему ломается (4 класса поломок)

Unity сериализует ссылки по `fileID` компонента. Меняешь `Text`→`TextMeshProUGUI` — у компонента новый `fileID`, поле текста другое (`m_text` у TMP вместо `m_Text`/`m_FontData` у Legacy). Всё, что на него ссылалось, отваливается **без compile-error**:

| # | Что отваливается | Симптом |
|---|---|---|
| 1 | **Per-instance `m_Text` override'ы** инстансов префаба-шаблона | все инстансы показывают текст шаблона: одинаковые заголовки табов, одна и та же цена на всех карточках |
| 2 | **Single сериализованные поля** скриптов (`[SerializeField] Text x`) | поле → `{fileID: 0}` → null → код пишет `x.text` → NRE / пустой UI |
| 3 | **Элементы массивов/списков** (`Text[]`/`List<Text>`, YAML-паттерн `- {fileID}`) | relink-проход, ловящий только `field: {fileID}`, пропускает элементы → null → NRE в `arr[i].text` |
| 4 | **Скрипты с полем типа `Text`, не мигрированные** (включая 3rd party и их потребителей) | объект стал TMP, поле осталось `Text` → не биндится → null → NRE |

> ⚠️ **Беречь вручную настроенный контент.** Геймпадные/keybind-подсказки и платформенные надписи (например туториальные инструкции под геймпад, glyph-хинты) — это ручная работа, которую легче всего потерять. Раз источник = git-база, они переносятся автоматически, **если инвентарь L1 их захватил**. Проверять отдельно.

> ⚠️ **`[FormerlySerializedAs]` тут НЕ спасает** — он переносит значение при переименовании поля, но при смене **типа** поля (`Text`→`TMP_Text`) ссылка всё равно рвётся. Нужен явный re-wire (L3).

### Процедура L0–L4 (один проход, идемпотентно)

**L0 — База и подготовка**
- [ ] Зафиксировать **чистый pre-migration коммит** как источник истины. Все оригиналы тянуть через `git show <commit>:<path>`, не из живого дерева.
- [ ] Если миграция уже частично сделана и поломана — **откатить tracked `.cs`/`.prefab` до базы** (`git restore`), оставив только новые ассеты-инфраструктуру (SDF-шрифты, `CustomFontSwitcher.cs`, `LocaleFontMapSO.cs`, `LocaleManager.cs`, LocaleFontMaps). Начать с чистой Legacy-базы. *(Если миграция не закоммичена — это просто discard рабочего дерева, без revert-коммитов.)*
- [ ] Карта `Legacy Font(guid) → TMP SDF(guid)` для всех базовых шрифтов. Несколько базовых → несколько `LocaleFontMapSO` (по одному на default-шрифт, CJK-поля общие).

**L1 — Инвентарь ПЕРЕД конвертацией (ключевой шаг, который проваливают)**
По git-базе построить карту-«слепок» на каждый `UnityEngine.UI.Text` в scope:
- [ ] стабильный `fileID` компонента + его GameObject (`fileID`/path/name) + префаб/сцена;
- [ ] **все** настройки: `text`, `font`(guid), `fontSize`, `color`, `fontStyle`(bold/italic), `alignment` (`TextAnchor`→TMP `alignment`), `horizontalOverflow`/`verticalOverflow`→`enableWordWrapping`/`overflowMode`, `lineSpacing`, `richText`, `raycastTarget`, `resizeTextForBestFit`→autosize+min/max, `maskable`, alpha;
- [ ] шаблон (nested в другие префабы) или инстанс;
- [ ] **inbound-ссылки** — grep по ВСЕМ префабам+сценам на этот `fileID`: `имяПоля: {fileID}` (single), `- {fileID}` (элемент массива/списка), и per-instance override'ы в блоках `--- !u!1001` (`m_Text`/`m_FontData`). Записать (источник, скрипт-компонент, имя поля/индекс).

**L2 — Код ПЕРВЫМ ДЕЛОМ (до префабов)**
- [ ] `grep -rn "UnityEngine.UI.Text" Assets/**/*.cs` — все `.cs` (включая 3rd party и **потребителей**). Сменить `Text`→`TMP_Text` (`using TMPro;`): поля, локальные переменные, параметры, свойства.
- [ ] 3rd party: мигрировать не только хранилище ссылки, но и код, который её читает/пишет. Типовая связка: ссылку **хранит** один скрипт плагина (класс-конфиг индикатора/виджета), а читает её **другой** — причём нередко через **локальную переменную** в методе (`Text t = indicator.distanceText;`). Грепать не только поля, но и локальные объявления, параметры и возвращаемые типы, иначе либо не скомпилится, либо поле молча не забиндится.
- [ ] Скомпилировать **до** конвертации префабов (`refresh_unity`+`read_console`) — типы должны существовать, иначе ссылки не забиндятся на TMP.
- [ ] Решить, какие 3rd party оставляем Legacy (если есть) — их текстовых детей НЕ конвертировать (иначе `Text`-поле осиротеет).

**L3 — Конвертер префабов (шаблоны → контейнеры → сцены)**
- [ ] На каждом GO с Text: заменить на `TextMeshProUGUI`, перенести ВСЕ настройки из L1, повесить `CustomFontSwitcher` + нужный `LocaleFontMapSO`.
- [ ] **Сразу re-wire всех inbound-ссылок** из L1 на новый TMP `fileID`: single-поля, **элементы массивов/списков** (не забыть `- {fileID}`!), и per-instance `m_Text` override (восстановить текст инстанса как `tmp.text`).
- [ ] Конвертировать в **источнике** (nested-prefab) → инстансы унаследуют. Где у инстанса был override текста — восстановить именно на инстансе.

**L4 — Верификационный гейт (НЕ закрывать миграцию без него)**
- [ ] Reflection-скан по ВСЕМ префабам+сценам: для game-скриптов поля типа `TMP_Text`/`Text` (single + array/list), **только сериализованные** (`public` без `[NonSerialized]` или `[SerializeField]`; приватные не-сериализованные типа `_tmpText`, заполняемые в `Awake` через `GetComponent`, — игнор). Список null = кандидаты в регрессии.
- [ ] Каждый null классифицировать сверкой с git-базой: был `fileID` ненулевым → **регрессия, чинить**; был null/absent → опциональное поле → **allowlist** (документировать: мёртвые префабы с 0 ссылок, SDK-private, поля, что и в базе null).
- [ ] Компиляция чистая; диф настроек (text/size/color/align/wrap) нового TMP против инвентаря L1; в scope не осталось `UnityEngine.UI.Text` кроме намеренных исключений.
- [ ] Рантайм-прогон ключевых экранов (магазин, туториал, попапы, HUD, подсказки кнопок, кастомизация).

### Gotchas

- **🔴 Порядок L1 → L2 не переставлять: смена типа поля обнуляет ссылку СРАЗУ.** Как только `[SerializeField] Text x` стал `TMP_Text x`, Unity при загрузке ассета отдаёт по этому полю `null` — `SerializedObject` уже не видит старую цель. То есть **после L2 инвентарь ссылок построить нельзя**, только восстановить из git-базы YAML. Практический вывод: L1 гоняется по всем префабам И сценам ДО первой правки `.cs`. Если проворонил — сами файлы на диске ещё целы (Unity перезаписывает ассет только при сохранении), поэтому цели вытаскиваются парсингом base-YAML: для цели в том же ассете `field: {fileID: N}` → блок N → `m_GameObject` → путь; для цели в nested-инстансе **stripped-блок сам несёт `m_Script` целевого компонента** (можно сразу отличить Text) + `m_CorrespondingSourceObject`(guid+fileID источника) + `m_PrefabInstance` → путь = (путь `m_TransformParent`) + (имя инстанса из override `m_Name`) + (путь объекта внутри исходного префаба).
- **🔴 `[RequireComponent(typeof(Text))]` на соседнем скрипте ломает конвертацию МОЛЧА.** Unity отказывается удалять Text, от которого зависит другой компонент: `DestroyImmediate(text)` не срабатывает, а следующий `AddComponent<TextMeshProUGUI>()` возвращает **null** (на GO уже есть Graphic) → NRE внутри конвертера, префаб не сохраняется. Перед L3: `grep -rn "RequireComponent(typeof(Text))"` → менять на `TextMeshProUGUI` (не на абстрактный `TMP_Text`). В конвертере обязательно проверять результат `AddComponent` на null и падать с внятным сообщением, иначе диагностика уходит в NRE без имени объекта. Типовой источник — **демо/Examples-скрипты сторонних плагинов**, лежащие в том же канвасе, что и рабочий UI: из-за одного такого скрипта молча не конвертируется весь канвас.
- **UGUI mesh-эффекты `Outline`/`Shadow` на Text — двойная проблема.** (1) Они наследуют `BaseMeshEffect` с зависимостью от `Graphic`, поэтому **мешают удалить Text** (см. выше) — конвертер должен снимать их первым. (2) На TMP они **не работают вообще** (TMP не прогоняет `IMeshModifier`): обводка/тень у TMP живут в материале. Инвентарь L1 обязан фиксировать их наличие и настройки (цвет/дистанция) — иначе тихо потеряете читаемость белого текста на светлом фоне. Правильное восстановление — **несколько ОБЩИХ материалов** (`fontSharedMaterial`) с обводкой на комбинацию (шрифт × цвет × толщина), а не `fontMaterial` per-object (инстанс материала на каждый текст = потеря батчинга). Автоподбор толщины из пиксельной `effectDistance` — угадывание: собрать список и решить глазами.
- **Ссылки, сломанные ДО миграции, замаскируются под «регрессии» на L4.** Типовой случай: поле уже `TextMeshProUGUI`, а значение в YAML — Legacy `Text` (кто-то сменил тип поля раньше и не перевязал) → в рантайме там всегда был null. Инвентарь L1 такие не видит (Unity обнуляет при загрузке), а L4 покажет как null-поле. Классифицировать **только сверкой base-YAML на уровне конкретного блока компонента** (script guid + путь GameObject). Грубый греп «есть ли в файле непустое значение этого поля» даёт ложные срабатывания там, где в префабе N однотипных компонентов (напр. 11 кнопок покупки, из которых привязана одна). Заодно это шанс починить давний баг — цель теперь TMP, ссылку можно завести.
- **В смешанном проекте сначала найди СУЩЕСТВУЮЩИЕ TMP-шрифты.** Часть UI обычно уже на TMP, и ассеты называются как угодно (`Bebas.asset`, `Rubik SemiBold.asset`), поэтому поиск по имени `*SDF*` их не находит. Искать `AssetDatabase.FindAssets("t:TMP_FontAsset")` + смотреть `TMP_Settings.defaultFontAsset`, и мапить Legacy-шрифты на них. Иначе получите дубликаты атласов на тот же TTF (лишняя память, разные материалы → лишние draw call'ы). Если дубликаты уже создались — нужен отдельный проход remap (только по НЕ-nested компонентам, иначе наплодите per-instance override'ов шрифта) и удаление дубликатов после проверки на 0 использований.
- **🔴 TMP не наследует OS-фоллбэк шрифтов.** Если игра уже локализована и CJK/тайский/арабский/деванагари рендерились «сами» — это работал системный фоллбэк **динамических** Legacy-шрифтов (`fallbackFontReferences: []`, dynamic mode). У TMP такого нет: после миграции без fallback-ассетов эти локали дают квадраты. Проверять ДО начала: какие письменности есть в таблицах переводов и покрывает ли их базовый TTF. Решение (шрифты Noto + fallback-цепочка/атласы) — Stage 5.6, но **риск фиксировать явно на 5.5**, иначе миграция «зелёная», а половина локалей визуально мертва.
- **Проверять итог удобнее в рантайме.** Play-режим + `Resources.FindObjectsOfTypeAll<TMP_Text>()` (фильтр `gameObject.scene.IsValid()`) даёт живую картину: сколько TMP, у скольких `font == null`, и сколько осталось `UnityEngine.UI.Text` — ловит то, что статический скан по ассетам пропускает (динамически инстанцируемые из `Resources` префабы).
- **Ссылка целится в текст ВНУТРИ nested-prefab.** В YAML родителя это «stripped»-компонент (`m_GameObject: 0`, есть `m_CorrespondingSourceObject`/`m_PrefabInstance`). Резолвить через source GUID+fileID PrefabInstance, либо проще — конвертировать в **источнике** и дать инстансу унаследовать (для overridden-текста восстановить на инстансе).
- **`Unsupported type vector`** при `SaveAsPrefabAsset` некоторых world-префабов — давнее безобидное сообщение Unity, сейв проходит (проверить ре-сканом, что данные на месте).
- **Каскад через nested-инстансы неполный.** Источник-префаб правит большинство инстансов, но те, у кого массив/поле было **override'нуто** на инстансе, нужно перевязать отдельно — после правки источника ре-сканировать и добить остаток. Главный носитель такого override'а — **массив текстов в шаблоне, который переиспользуется десятком контейнеров** (`Text[]`/`List<Text>` на панели, вложенной в кассу, окружение, отдельные канвасы): в источнике массив перевязался, а в каждом контейнере лежит своя копия элементов.
- **СЦЕНЫ ссылаются на текст внутри мигрированных префабов → висячие ссылки.** Если скрипт **на сцене** держит `[SerializeField] Text/TMP_Text`, указывающий на текст-компонент внутри префаб-инстанса, то конвертация Text→TMP в этом префабе меняет fileID компонента, а ссылка из сцены (хранится по старому fileID) становится **null в рантайме** — БЕЗ изменения самого `.unity` (git его не пометит как изменённый). Симптом коварный: NRE НЕ в UI, а там, где UI-метод вызывается из игровой логики. Типовая цепочка: геймплейный метод (напр. «положить товар на склад») дёргает обновление текста подсказки → поле текста в панели туториала `null` → исключение обрывает метод **ДО** следующей строки, повышающей шаг туториала → **софт-лок**. **Поэтому L1/L4-скан обязан покрывать СЦЕНЫ** (`scene.GetRootGameObjects()` → reflection по сериализованным `Text/TMP_Text`-полям игровых скриптов), а не только префабы. Чинится перевязкой поля на нужный TMP в открытой сцене + `SaveScene`.
