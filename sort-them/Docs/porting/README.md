# Порт игры на консоли с Claude Code — с чего начать

Это **входная точка**. Здесь — как устроена связка «ИИ + эта папка» и как ею пользоваться, чтобы довести Unity-игру до консольного порта. Технические детали тут **не дублируются** — на них даются ссылки.

> Следующий шаг после этого файла — **`PORTING_PIPELINE.md`** (индекс пайплайна и маршрутизация по стадиям).

---

## 1. Что это за связка и кто за что отвечает

Портирование ведётся не «ИИ сделает всё сам», а как режиссура: ты ставишь задачи и принимаешь решения, ИИ исполняет и отчитывается, ты проверяешь.

| Участник | Роль |
|---|---|
| **Папка `porting/`** | Переносимый «мозг» методики: пайплайн, стадии, подводные камни, справочник SDK. Копируется в любой новый порт-проект целиком. |
| **Claude Code** (ИИ) | Исполнитель: читает доку, пишет/правит код, ходит в Unity через MCP, ведёт лог. |
| **Unity MCP** | «Руки» ИИ в открытом Editor: сцены, префабы, скрипты, консоль, плеймод, скриншоты. |
| **Ты (разработчик)** | Режиссёр и ревьюер: формулируешь задачи, **принимаешь решения** (архитектура, баланс, контент, что выпиливать), проверяешь результат. |

**Что ИИ НЕ решает сам** (всегда согласует с тобой): что удалять из SDK, как поступать с рекламой/IAP, нужна ли локализация, маппинг кнопок, любые изменения геймплея/баланса/контента.

## 2. Предпосылки (чеклист)

Перед стартом убедись, что всё на месте (пошаговая установка тут не описана — это просто список того, что должно работать):

- [ ] **Claude Code CLI** установлен и запускается в папке проекта.
- [ ] Скилл **`/unity-analyze`** установлен — инструкция и исходник в `SKILL-unity-analyze.md`.
- [ ] Есть **доступ к мощной модели** (рекомендуется Opus) — порт-задачи нетривиальные.
- [ ] **Unity** нужной проекту версии установлен, проект открывается.
- [ ] Пакет **MCP for Unity** (`com.coplaydev.unity-mcp`) подключён, Editor открыт и MCP отвечает.
- [ ] Папка **`porting/`** лежит в корне проекта (эта папка — её и копируешь из прошлого порта).
- [ ] (Опц.) IDE (Rider/VS) для ручного чтения кода.

> Список инструментов Unity MCP — в `MCP_REFERENCE.md`.

## 3. Пошаговый старт («первый день»)

Высокоуровневая последовательность. Канонический разбор — в `PORTING_PIPELINE.md` (разделы **«Стартовый протокол нового проекта»** и **«Протокол сессий»**); здесь — общая картина.

1. **Скопируй `porting/`** в корень нового проекта.
2. **Сначала собери проект, не анализируй.** В обычном (чистом) чате почини ошибки компиляции: версия Unity, битые ссылки, отсутствующие пакеты.
   - ⚠️ **Почему первым:** весь дальнейший порт идёт через Unity MCP, а MCP даёт осмысленный результат только на Editor **без ошибок компиляции**. По сломанному проекту сцены не грузятся — анализ будет мусорным.
   - **Порт-доки на этом шаге не открывай.** Это обычная починка сборки, порт-специфики тут нет — `porting/` пока не нужна.
3. **Когда Editor чист и MCP отвечает** → запусти скилл **`/unity-analyze`**. Он изучит проект и сгенерирует:
   - `CLAUDE.md` — инструкции проекта + «порт-станза» с триггер-словами;
   - `ARCHITECTURE.md` — карта проекта (сцены, иерархии, системы);
   - `PROGRESS.md` — лог порта с заготовкой по каждой стадии.
   - ⚠️ **`/init` не запускай** — `/unity-analyze` полностью заменяет его для Unity (иначе получишь конфликтующие `CLAUDE.md`).
4. **Прочитай сгенерированное** — это твоя карта проекта.
5. **Дальше — по фазам**, каждая в своём чате. О портинге ИИ «рассказываешь» **не сразу, а когда дошёл до конкретной фазы**: новый чат → `PORTING_PIPELINE.md` (индекс) → файл нужной стадии → `PROGRESS.md`.

## 4. Плейбук работы с ИИ

Главное — не «как настроить», а **как вести работу**, чтобы ИИ был полезным и предсказуемым.

- **Новый чат на каждую фазу.** Длинный чат теряет детали при компакте; чистый старт дешевле и надёжнее. В начале сессии ИИ читает `CLAUDE.md` → `PORTING_PIPELINE.md` → файл текущей стадии → `PROGRESS.md`.
- **Plan mode для крупных задач.** ИИ сперва составит план — **прочитай и одобри его до запуска**. Мелкие правки можно сразу.
- **Триггер-слова работают сами.** В `CLAUDE.md` есть станза: слова вроде «геймпад», «сейвы», «глиф», «вибрация», «локализация» автоматически направляют ИИ в нужный stage-файл. Не нужно пересказывать доку руками — просто формулируй задачу по делу.
- **Всегда проверяй вывод.** «Готово» без проверки не принимать:
  - компиляция — ИИ смотрит `read_console`;
  - поведение — запуск в Play;
  - визуал — скриншот сцены через MCP.
- **Решай сам в спорных точках.** Правки префабов/сцен (сверяйся с `GOTCHAS.md` — там молчаливые ловушки MCP), архитектурные развилки, баланс/контент — это твои решения, ИИ должен спросить.
- **Фиксируй прогресс.** В конце фазы проси обновить `PROGRESS.md`: статус, принятые решения, новые подводные камни. Это «память» проекта между чатами.
- **Держи ИИ в рамках.** Без рефакторинга и фич сверх запроса; без комментариев в коде без явной просьбы (правило пайплайна).
- **ИИ не должен выдумывать API.** Если речь про SDK — требуй сверки с `UPSCALE_SDK.md` и живым кодом. Не уверен — пусть спросит, а не угадывает.

## 5. Сквозной пример (как это выглядит в работе)

📍 Реальный кейс из Captive — баг «положить предмет на место» на не-английских локалях. Показывает полную петлю.

1. **Запрос (ты):** «На русском книга и фонарь не возвращаются на место — просто падают. На английском работает. Разберись и почини».
2. **ИИ читает код** взаимодействия инвентаря (`InventoryUI`, `PlaceItem`) — триггер-слова направили его к нужной логике.
3. **Находит причину:** ветка решалась сравнением **локализованного** текста кнопки с литералом `"Place"`. На EN совпадало, на RU/FR/SV текст другой («Положить»/"Placer"/"Placera") → срабатывал обычный Drop вместо установки. Баг ломал **все** не-EN локали.
4. **План + правка:** добавил read-only `PlaceItem.CanPlace(item)` (проверка состояния, без текста), `InventoryUI.DropButton` теперь ветвится по нему, а не по подписи кнопки. Локализацию подписи не трогал.
5. **Проверка:** компиляция чистая; Play-проверку (RU/EN, книга+фонарь) подтвердил ты.
6. **Лог:** запись в `PROGRESS.md` с причиной и фиксом.

**Мораль:** ИИ сам не догадается, что «сравнение текста» — это локале-зависимый антипаттерн, **пока ты не дашь чёткую задачу и не проверишь результат**. Связка работает, когда человек ведёт.

## 6. FAQ и типовые затыки

| Симптом | Что делать |
|---|---|
| MCP не отвечает / анализ выдаёт мусор | Проверь, открыт ли Editor и **нет ли ошибок компиляции**. Сначала зелёная сборка — потом анализ. |
| ИИ «забыл» контекст в длинном чате | Начни **новый чат на фазу**. `PROGRESS.md` и `/unity-analyze` восстановят картину. |
| ИИ придумал метод/класс SDK, которого нет | Потребуй сверку с `UPSCALE_SDK.md` и живым кодом `Assets/UpscaleSDK/`. |
| Правки префаба «не сохранились» / задвоились элементы | Это известные ловушки — смотри `GOTCHAS.md` (MCP + Prefab Stage). |
| Не понимаю, с чего начать на новой задаче | `PORTING_PIPELINE.md` — индекс и таблица маршрутизации «стадия → файл». |
| ИИ полез делать лишнее (рефакторинг/фичи) | Останови; правило пайплайна — только то, что запрошено. |
